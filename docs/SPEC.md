## 2. 告示牌（`/board/`）数据结构与同步规格（已实现）
`js/board.js` 维护统一的状态结构（向后兼容旧版纯数组格式）：
- `version`: `2`
- `updatedAt`: 毫秒级时间戳
- `scratchpad`: `{"text": "跨设备临时粘贴的链接、命令或灵感片段...", "updatedAt": 1792044000000, "history": []}`
- `tasks`: 数组，每项包含 `id`、`title`、`due`、`time`、`done`、`made`、`private`（是否仅主人可见）、`updatedAt`。`pin` 可选 `red/blue/green/gold` 手动分类，空值沿用旧的到期紧迫度配色；`pinnedAt` 标记粘贴置顶时间，`archive` 为 `local/public` 或空。见 §9。
- V8 删除条目保留为 `{ "id": "...", "deleted": true, "updatedAt": 123 }`，不保留正文。删除记录参与云端/GitHub 时间戳合并，在列表和匿名响应中隐藏；撤销生成更新的正常条目。旧设备的过期副本不能复活已删除任务。
- 本机缓存记录 `scratchSyncedAt`，只有远端确认后才更新；界面区分本机保存、等待同步、远端确认和本机保存失败。

三级存储与同步降级机制：
1. **自建云服务器模式（优先）**：当配置了主人口令（Passkey）且 `/api/board` 可达时，通过 `GET /api/board` 与 `PUT /api/board` 实时同步。
2. **GitHub API 模式（次选）**：在纯静态托管（GitHub Pages）且配置了 GitHub PAT 时，读写仓库中的 `board.json`。
3. **本地沙盒模式（默认）**：未解锁口令的访客读写浏览器本地 `localStorage`，界面明确提示「本地暂存（未登录口令不对外公开）」，初次进入且为空时自动预置欢迎指引便签供访客测试，且服务端自动过滤掉 `private: true` 的私密条目。

## 3. 云端后端 API 契约（`server/app.py`）
**已实现**：
- `POST /api/auth/verify`：校验请求头 `X-Passkey` 是否与服务端环境变量 `RICARDO_PASSKEY` 匹配，返回 `{"ok": true}`。
- `GET /api/board`：已鉴权返回完整 `board` 数据（含私密任务与 `scratchpad`）；未鉴权仅返回公开任务且隐藏私密暂存贴。
- `PUT /api/board`：需 `X-Passkey` 鉴权。在同一 `BEGIN IMMEDIATE` 事务中读取、按任务 `id` 与 `updatedAt` 合并并写回，避免并发覆盖。
- `GET /api/summary`：公开返回 `nowStatus` 与最近 3 条日志的 `id/date/text`，不含图片，供首页与独立近况页使用。
- `GET /api/logs?limit=10&before=<id>`：公开返回 `{"nowStatus": "...", "logs": [...], "nextBefore": 123}`；默认 10 条、最多 20 条，按 ID 倒序，下一页只取小于游标的记录；末页 `nextBefore` 为 `null`。配图只在日常列表响应中返回。
- `POST /api/logs`：需 `X-Passkey` 鉴权。支持新增日常流水或更新 `nowStatus`。
- `DELETE /api/logs?id=<id>`：需 `X-Passkey` 鉴权。删除指定日常条目。

**V7 扩展（已实现）**：
- 日常记录扩展 `mood`、`weather`、`image`、`imageAlt`、`sourceId`。图片由客户端压缩为最长边 ≤1200px 的 JPEG，服务端接受 JPEG/PNG/WebP data URL（解码后 ≤400KB），拒绝 SVG 与无效格式。旧库启动时幂等迁移；`sourceId` 非空时唯一，重复 POST 返回同一顶层 `id`。
- `farm.logs.v1` 只存公开日志缓存；`farm.logs.local.v1` 独立保存本机记录，在线拉取不覆盖、不自动公开。公开本机记录需口令与明确确认。
- V8 首页使用独立的 `farm.logs.summary.v1` 缓存，只展示公开记录；日常页的“更多日常”按游标追加。接口不可用时保留缓存或页面自带的静态文字。
- `GET /api/messages`：公开返回最新留言/漂流瓶列表 `{"messages": [{"id": 1, "text": "...", "author": "路过的农夫", "badge": "🌾", "created_at": 1792044000}]}`（Task 29）。
- `POST /api/messages`：公开提交简短访客打卡/漂流瓶。单条限长 60 字，IP 速率限制（每 IP 10 分钟最多 2 条），防 XSS 强制纯文本存储（Task 29）。

## 7. 轻量级社交留痕：木屋留言簿与池塘漂流瓶规格（已实现 · V7 Task 29）
- **双通道留痕机制**：
  - **池塘漂流瓶（Fishing Drift Bottle）**：在池塘垂钓结算时，设定 15% 概率触发捞起漂流瓶动画，随机展示近期访客留言或木屋生活语录；
  - **篝火打卡册（Campfire Guestbook）**：角色靠近篝火按空格或点击时，弹出便携式羊皮纸留言板，允许访客挑选预设像素头像并提交不超过 60 字的暖心寄语；
  - **降级与防刷策略**：服务端不可达（纯 GitHub Pages 静态模式）时自动降级回内置静态语录池与 LocalStorage 本地写存；严格限制字数与高频提交，渲染时全链路使用 `textContent` 规避 XSS 注入。
  - **保存反馈（V9 Task 47）**：本机写入成功只表示当前浏览器可见，不会自动公开；写入失败时保留输入并提示复制后重试，不将失败留言加入列表或漂流瓶池。只有服务端确认成功后才提示其他访客可见；服务端明确拒绝时保留输入及错误信息。

## 12. V8 自建部署与数据迁移

- `RICARDO_PASSKEY` 必须显式设置；空值以及旧默认值 `dev-passkey` / `please-change-me` 会拒绝启动。不要将口令写进仓库。
- 原生运行默认使用 `${XDG_DATA_HOME:-~/.local/share}/my-ricardo` 保存数据库与 `backups/`，可通过 `RICARDO_DATA_DIR` 指定绝对路径。后端与 `server/backup.sh` 使用同一变量。
- 从旧原生部署升级：先停止后端，备份并将整个 `server/data/` 目录移至所选的私有数据路径，再使用相同 `RICARDO_DATA_DIR` 启动后端和备份任务。如果发现旧库仍在原处且新位置没有数据库，启动会中止，避免误建空库。本文只说明迁移步骤，不会自动移动现有数据。
- Docker 保留宿主机 `./server/data`，容器内改挂到 `/data`，由镜像的 `RICARDO_DATA_DIR=/data` 读取；已有 Compose 用户无需移动宿主机数据库。宿主机备份时将 `RICARDO_DATA_DIR` 设置为该目录的绝对路径。
- 备份使用 `server/backup.sh` 的 SQLite 在线备份接口，包含 WAL 中已提交的数据，校验快照后再发布文件；权限为 600，保留 30 天。源数据库不存在时返回失败，不创建空数据库。Compose 内执行 `docker compose exec -T app sh server/backup.sh`，文件保存在宿主机 `server/data/backups/`；定时执行与异地副本需在目标服务器上配置并验收。
- 恢复前停止应用写入并完整保留现有数据目录作为回退副本；在新的数据目录中把选定快照放为 `ricardo.db`，设置应用所需的属主和权限，不混用旧库的 WAL/SHM 文件。启动应用后核对记录、鉴权和公开接口；需要回退时停应用并恢复原目录。恢复演练先使用独立临时目录，不能直接覆盖在线数据库。
- `.dockerignore` 排除数据库、环境变量文件和 Git/智能体私有目录。静态处理器的 GET/HEAD 共用公开目录白名单，拒绝私有路径和目录列表。

## 13. 工作台备份与恢复（V9 Task 48）
- 入口位于 `/board/` 的“备份与恢复”折叠区；下载 JSON 文件，选择文件后先预览，明确确认后才写入，取消与文件校验失败不修改数据。支持整页打开及 `farm:page` 切页初始化。
- 文件格式为 `{format: "ricardo-workbench", version: 1, exportedAt, board: {tasks, scratchpad}, localLogs}`。导出合并待同步队列后的全部待办（含私密、已完成及删除记录），剪贴板正文与最近 5 条历史，以及本机日常和配图。
- 按内容字段白名单读写，不包含 `board.key`、`ricardo_passkey`、`ricardo_owner`、仓库地址、同步版本或公开日常缓存；导入不改变当前凭据。备份内含私密内容，界面提示妥善保管。
- 待办按 ID 与原始 `updatedAt` 合并；同 ID 仅接受时间戳更大的备份条目，保留较新/相同时间的本机记录及删除标记。剪贴板复用现有 `pickPad` 规则，保留较新正文并去重合并最多 5 条历史。
- 本机日常按 `id` 或非空 `sourceId` 去重，已有同条记录保留，新条目强制为 `local: true`；恢复不会调用日常发布接口，也不会导入公开缓存。文件只接受本站格式，校验时间戳、记录字段与现有 JPEG/PNG/WebP 配图格式。
- 确认时按最新内存状态重新计算合并；正在同步时提示等待再确认。连接 GitHub 时将接受的待办追加到现有队列，保持原时间戳；自建后端沿用现有合并接口。本机保存成功后才继续当前同步通道，远端确认由原同步状态栏显示。
- 写入本机日常及告示牌两个存储项后才替换内存状态。第二项写入失败时还原第一项；存储不可用或空间不足时保留预览和备份以供重试，若回退也失败则明确报告可能部分导入，不提示恢复成功。

## 14. 发文与订阅维护（V9 Task 49）
- `notes/catalog.json` 统一维护每篇文章的 `slug/title/short_title/date/tag/description/preview`。正文仍为独立 HTML；日期用于倒序排列，`preview` 为首页摘要，`description` 为订阅摘要。
- 新增文章：`python3 tools/new-note.py <slug> <draft.md> --date YYYY-MM-DD --tag 分类`，可指定 `--short-title`。命令生成当前双主题、canonical、社交卡片、PWA 与公共交互脚本配置的文章页，登记清单，并更新笔记列表、首页最新一篇、Atom 订阅源、站点地图及 Service Worker 预缓存。
- 模板支持段落、二级标题、无序列表、行内代码、粗体与链接。复杂排版在生成后编辑正文；已有路径拒绝覆盖，非法 slug/日期在写入前拒绝。
- 编辑清单后运行 `python3 tools/new-note.py --sync`，只重建生成区域与入口，不改现有文章正文。新增文章自动纳入静态检查和字库扫描，无需在两个 Python 文件中逐篇登记。
- 发文与同步命令通过 `uv run --no-project --with fonttools --with brotli` 调用现有字库生成器，然后运行 `tools/check.py`；需要本机 `uv`，首次安装工具包需要网络。检查不通过时命令返回失败，保留生成文件供修正，再运行 `--sync` 验收；命令不会提交或部署。
- 笔记页提供可见 Atom 订阅入口，首页、笔记目录和文章页提供订阅发现链接。静态检查核对清单文章的目录、订阅、站点地图和离线入口；离线匹配由预缓存清单确定，支持新文章、`index.html` 与子目录托管。

## 16. 弹窗键盘与焦点生命周期（V9 Task 51）
- 留言与小游戏复用 `js/messages.js` 提供的 `FARM_MODAL`；公共脚本保持 `messages.js` 在 `games.js` 之前加载。打开时记录入口焦点，隔离背景并聚焦窗口内的初始操作。
